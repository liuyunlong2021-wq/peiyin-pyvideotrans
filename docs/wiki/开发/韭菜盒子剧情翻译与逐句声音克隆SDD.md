# 韭菜盒子剧情翻译与发言轮次声音克隆 SDD

> 日期：2026-07-30  
> 状态：克隆校对工作台、人物建议与音频优先角色表演参考库已实施；待真实整集 A/B
> 范围：仅修改 `peiyin-pyvideotrans`；`jiucaihezi-app` 只作只读参考

## 1. 一句话目标

将一集约两分钟的中文短剧识别并翻译为自然的美式英语对白，由用户在翻译校对窗口确认相邻字幕是否属于同一次连续发言，再以完整发言轮次的中文原声克隆英文语音，最后按逐句字幕时间轴合成完整英文音频或视频。

## 2. 成功标准

1. 用户只需配置 API URL 和 API Key；默认 URL 为 `https://api.jiucaihezi.studio/v1`，并可从设置页前往 `https://api.jiucaihezi.studio/keys`。
2. 翻译默认使用 `gemini-3.6-flash`，也可在韭菜盒子 API 设置中选择其他兼容模型；一次提交整集 SRT，使人物关系、指代、语气和前后剧情可共同参与翻译。
3. 输出字幕与输入字幕保持严格一一对应，行号和时间戳不变；英文适合美国短剧口语和 TTS 配音，不做逐字直译。
4. 字幕始终逐句保留；连续发言可由用户合并为一次克隆，`A → B → A` 必须形成三个独立轮次。
5. 继续使用现有音频调速、补静音、时间轴对齐和最终合成流程。
6. API Key 不写入日志、Wiki、测试样例或任务输出。
7. 克隆模式的校对窗口以字幕和发言轮次为主工作区，不显示无效的预设音色分配功能。

## 3. 已有能力

当前项目已具备主链路，不重写：

- `BaseTrans` 在开启“发送 SRT”和 `aitrans_context` 后，会把整集字幕作为一个 SRT 批次交给 AI 翻译渠道。
- `_stage_dubbing.py` 为每条英文字幕保留对应中文原文 `ref_text`、时间戳和输出文件名。
- `_create_ref_from_vocal()` 按每条字幕时间戳裁出 `ref_wav`。
- `_rate.py` 负责配音片段调速、补静音、时间轴对齐和完整音频拼接。

韭菜盒子只读参考实现已证明云端媒体链路包含：Bearer Key 鉴权、参考音频上传、`/v1/audio/speech` 提交、异步任务轮询和音频结果下载。实施时只复制完成当前任务所需的最小请求合同，不复制 Vue、Pinia、Tauri、媒体任务 Store 或画布编排。

## 4. 翻译设计

### 4.1 模型和调用

- 渠道：新增“韭菜盒子剧情翻译”。
- Base URL：用户可配置，默认 `https://api.jiucaihezi.studio/v1`。
- 模型：主工作区的翻译渠道下拉框直接提供两个免费渠道和五个韭菜盒子兼容模型；翻译与人物/轮次建议共用该选择。
- 协议：复用现有 OpenAI-compatible `POST /chat/completions` 调用和翻译缓存。
- 模式：该渠道强制使用完整 SRT 上下文，不依赖用户另外开启高级选项。

### 4.2 剧情翻译提示词合同

提示词必须要求模型：

1. 先理解整集事件、人物关系、称谓、指代、隐含意图和情绪变化，再翻译每条字幕。
2. 输出当代美国影视对白，而非书面英语或中文句式的英文替换。
3. 保留角色身份、权力关系、攻击性、暧昧、讽刺、威胁和笑点，不擅自弱化或增写剧情。
4. 使用自然缩写和口语表达；根据字幕时长压缩台词，使其适合配音。
5. 严格保持 SRT 块数量、行号、顺序和时间戳，不合并、不拆分、不移动语义到相邻字幕。
6. 人名、地名和专有词在整集中保持一致，并继续遵守现有术语表。
7. 只输出 `<TRANSLATE_TEXT>` 包裹的合法 SRT，不输出分析、剧情总结或解释。

提示词作为产品运行时资源放在 `videotrans/prompts/srt/`。不创建 Codex Skill：Codex Skill 不会自动进入桌面应用的模型请求，单独创建只会形成无法执行的旁路文档。若未来产品增加可选择、可加载的翻译 Skill 机制，再将这份提示词合同迁移为产品 Skill。

### 4.3 人物与发言轮次建议

不把 `Speaker1:` 写入 SRT 字幕正文。现有翻译响应必须继续保持纯 SRT，避免人物前缀进入最终字幕和 TTS 文本。

剧情翻译成功后，仅在“韭菜盒子剧情翻译 + Qwen3-TTS 本地 + clone”组合下，使用同一组 API URL、Key 和用户选定模型发起一次独立轻量请求。输入包含整集中文、整集英文、时间轴以及 `speaker.json` 的音频说话人提示；输出只包含与字幕逐行对应的 JSON：

```json
[
  {"line": 1, "speaker": "Speaker1", "join_previous": false},
  {"line": 2, "speaker": "Speaker2", "join_previous": false},
  {"line": 3, "speaker": "Speaker2", "join_previous": true}
]
```

建议写入任务缓存目录的 `turn_suggestions.json`，不直接作为配音合同。必须校验行数、行号、人物标签和布尔类型；请求或校验失败时记录不含 Key 的警告并回退 `speaker.json`，不得中断已经成功的翻译。

校对窗口预填优先级固定为：已有合法 `turns.json` > `turn_suggestions.json` > 现有音频说话人及 1000ms 间隔规则。人物标签仅帮助人工识别 `A → B → A`，最终 Qwen3-TTS 仍只消费人工保存的 `turns.json`。

## 5. 发言轮次声音克隆设计

“韭菜盒子云端克隆”和本地 Qwen3-TTS 继续消费现有克隆字段：

```text
英文输出文本  = data_item.text
中文参考文本  = data_item.ref_text
参考声音文件  = data_item.ref_wav
生成文件      = data_item.filename
目标语言      = English
```

最小请求流程：

```text
ref_wav
  -> 编码为 data:audio/wav;base64 节点值
  -> POST /v1/audio/speech（声音克隆应用合同；服务端适配器负责上传）
  -> 同步获得音频 URL，或按返回 taskId 轮询
  -> 下载并转换为 data_item.filename
  -> 交回现有对齐与合成流程
```

### 5.1 人工分组合同

翻译完成、配音开始前，复用现有字幕校对窗口增加“接上句”列：

- 未勾选：从本句开始新的克隆任务；
- 勾选：本句与上一句合为同一次克隆；
- 第一行固定不可勾选；
- `speaker.json` 只负责自动预填，人工勾选结果是最终依据；
- 只允许时间轴相邻字幕合并，不跨行寻找相同人物；
- 字幕文本仍可逐句编辑、保存和最终显示。

保存按钮显示“保存翻译与分组，开始配音”，并将分组写到目标字幕同目录：

```json
[false, true, false, true]
```

文件名固定为 `turns.json`，数组与字幕行严格一一对应。优先读取已有合法文件；不存在时，仅在相邻说话人相同且原声间隔为 `0..1000ms` 时预勾选。缺少说话人数据时全部不勾选。

### 5.2 配音执行

配音阶段仅在 Qwen3-TTS 本地克隆中消费 `turns.json`。文件存在且数组长度、类型合法时完全服从人工结果；文件缺失或损坏时保留现有 `speaker.json` 自动合并作为兼容回退。合并后的单次 TTS 任务使用整段英文、整段中文参考文本和从首句开始到末句结束的原声音频，生成后仍由现有 `_subtitle_items` 展开回逐句字幕时间轴。

基础链路不建立全局 voice ID。下一阶段只增加用户明确选择的“剧集角色库目录”，不建设账号级人物管理系统。短句、重叠对白或背景音乐仍会限制克隆质量，任何参考音替换都必须限定在人工确认的同一角色内，不能静默改用其他人的参考音频。

### 5.3 克隆校对工作台

仅当配音渠道为 Qwen3-TTS 本地且主角色为 `clone` 时，现有通用角色分配窗口切换为克隆校对模式：

- 单视频交互明确显示步骤：第 1 步“校对中文字幕并开始翻译” → 第 2 步“校对英文与发言轮次” → 可选步骤“复核配音后的英文字幕”；
- 第 2 步必须使用任务启动时冻结的 `voice_role` 判断 clone 模式，不读取可能已变化的主界面下拉框；

- 顶部只保留“字幕句数 / 克隆段数”和英文字幕查找替换，不自动倒计时继续；
- 主区域使用横向分割，左侧为约 280px 宽的 9:16 视频预览和播放状态，右侧表格占剩余空间；
- 表格隐藏 `Sel` 和“配音角色”，保留“行、人物建议、接上句、播放、英文字幕、中文原文”，时间轴压缩显示；
- 人物建议优先显示模型建议，缺失时显示音频说话人标签，但不参与最终音色选择；
- 隐藏说话人角色分配、给选中字幕指定角色、配音角色下拉框和旧试听功能；
- 隐藏“不保存只继续”，保留“打开输出目录”“终止任务”和唯一主按钮“确认字幕与分组，开始配音”；
- 打开窗口时不自动播放，用户点击行内播放按钮试听对应原声。

非 clone 或其他 TTS 渠道继续使用原有通用角色分配界面，不改变现有能力。

## 7. 失败与安全

- 缺少 URL、Key 或参考音频时，在付费请求前失败并指出缺失项。
- `401/403` 显示 Key 无效或无权限；`429` 显示请求频繁；任务失败显示服务端消息但不得拼入 Key。
- 单条克隆失败时停止任务并保留缓存，不以静音伪装成功，用户修复后可利用已有翻译和已完成片段重试。
- 默认单线程提交云端克隆，避免付费任务并发、限流和乱序；确认服务额度和稳定性后再考虑提高并发。
- 下载结果只接受服务端返回的 HTTP(S) 音频地址或合法音频内容。
- `turns.json` 非布尔数组或与字幕行数不一致时记录警告并回退自动分组，不中断已有任务。

## 12. 音频优先角色表演参考库 SDD（2026-07-31）

### 12.1 决策与目标

声音克隆的主证据必须来自音频，而不是只根据字幕文字或画面猜测情绪。下一阶段以完整发言轮次的原声为输入，识别角色、情绪和声音事件，并在同一角色的参考音中找到最接近当前表演的清晰长音频，解决短参考音导致的音色漂移。

核心关系分为两条，不能混用：

```text
生成关系：字幕行 -> 发言轮次 -> 目标英文音频
参考关系：发言轮次 -> 稳定角色 ID -> 情绪表演向量 -> 同角色参考音
```

成功标准：

1. 当前轮次原声清晰且达到 3 秒时，继续优先使用当前原声，保留最准确的现场情绪。
2. 当前轮次过短或质量不合格时，只在同一角色的参考音中检索，不跨角色借音。
3. 参考音选择以 `emotion2vec+ large` 的音频情绪向量为主，离散标签只用于解释和初筛。
4. `emotion2vec+ large` 是首版唯一必经的情绪模型；SenseVoice 只在用户本来选择它做 ASR 时保留已有情绪与声音事件结果，不额外运行第二遍。
5. Gemini 继续使用整集剧情判断人物关系和语义情绪，但不替代音频情绪识别。
6. 角色库按剧保存并可跨集复用；新参考音必须经人工确认后入库，不能自动污染已有角色。
7. 不引入向量数据库、全局人物管理服务或多模态训练框架。

### 12.2 模型选择与边界

#### SenseVoiceSmall

当前项目已经注册 `SenseVoiceSmall`，现有识别实现会先取得包含 `<|ANGRY|>`、`<|Cry|>` 等标签的富文本，再通过 `_remove_unwanted_characters()` 删除全部 `<|...|>` 标签。第一步只需在清理字幕正文前解析并保存这些标签，不重写 ASR。

SenseVoiceSmall 提供：

- 情绪：`happy`、`sad`、`angry`、`neutral`、`fearful`、`disgusted`、`surprised`；
- 事件：`BGM`、`speech`、`applause`、`laughter`、`cry`、`sneeze`、`breath`、`cough`；
- ASR、语种识别和低延迟推理。

它的标签粒度较粗，定位为已有 ASR 结果的兼容信息，而不是第二个情绪分类器。未选择 SenseVoice 作为 ASR 时不额外加载；即使选择了 SenseVoice，首版参考音检索仍只使用 `emotion2vec+ large` 的 embedding。

#### emotion2vec+ large

`emotion2vec+ large` 是主情绪模型，约 300M 参数，输出九类情绪分数和情绪 embedding：`angry`、`disgusted`、`fearful`、`happy`、`neutral`、`other`、`sad`、`surprised`、`unknown`。

分类分数表示判断置信度，不代表情绪强度。产品不得把 `angry=0.9` 显示为“愤怒强度 90%”。参考音匹配使用 embedding 的余弦相似度；标签只负责过滤明显不相容的候选和向用户解释结果。

#### 不进入主流程的模型

- Mage-VL 只处理视觉帧，不处理音频；仅在音频、剧情和人工判断冲突时作为可选视觉证据，不进入首版关键路径。
- MERTools 是多模态情绪研究与比赛工具箱，不是可直接嵌入的单一推理模型，且部分数据和服务限定研究/非商业使用；首版不接入。

### 12.3 最小数据流

```text
现有说话人分类生成的 speaker.json
  -> Gemini 结合整集剧情给出人物与轮次建议
  -> 人工确认 turns.json 和 speaker_assignments.json
  -> 按完整发言轮次裁出已分离人声
  -> emotion2vec+ large：标签、分数、情绪 embedding
  -> 若本来使用 SenseVoice ASR：沿用其声音事件元数据
  -> 当前原声质量判断
     -> 合格且 >= 3 秒：使用当前原声
     -> 过短/不合格：在同角色参考库内做 embedding 最近邻检索
  -> 人工确认低置信度或冲突项
  -> Qwen3-TTS 1.7B 克隆
  -> 用户可将本集优质片段补充进角色库
```

首版不做模型加权打分。决策优先级固定为：人工结果 > 角色身份约束 > 当前音频 > emotion2vec 检索 > 中性参考音回退。Gemini 只给人物和语义建议，SenseVoice 事件只用于提示参考音风险，两者都不参与 embedding 排序。

### 12.4 角色库目录与数据合同

用户为同一部剧选择一个角色库目录；后续集数继续选择该目录即可复用。首版使用普通文件和 JSON：

```text
voice_library/
├── library.json
├── refs/
│   └── linxia_angry_01.wav
└── embeddings/
    └── linxia_angry_01.npy
```

`library.json` 最小合同：

```json
{
  "version": 1,
  "characters": [
    {
      "id": "linxia",
      "name": "林夏",
      "identity_reference": "linxia_neutral_01",
      "performances": [
        {
          "id": "linxia_angry_01",
          "audio": "refs/linxia_angry_01.wav",
          "embedding": "embeddings/linxia_angry_01.npy",
          "text": "你凭什么这么对我",
          "duration_ms": 4200,
          "emotion": "angry",
          "events": [],
          "source": {"episode": "01", "line_start": 18, "line_end": 19},
          "approved": true
        }
      ]
    }
  ]
}
```

逐行人物确认结果单独保存为 `speaker_assignments.json`，与现有 `turns.json` 保持兼容：

```json
["linxia", "chenyang", "linxia", "father"]
```

数组必须与字幕行严格一一对应。`speaker.json` 和模型建议只能预填，人工保存的稳定角色 ID 才能跨集复用。embedding 使用 `.npy` 文件，不把数百个浮点数塞进 JSON；参考数量很少，使用 NumPy 线性扫描，不引入 FAISS 或数据库。

### 12.5 参考音解析规则

对每个完整发言轮次：

1. 从已有分离人声裁切原声，参考文本必须与裁切内容严格对应。
2. 当前轮次达到 3 秒、无多人重叠且没有明显 BGM/噪声时，优先使用自身。
3. 否则先按 `character_id` 过滤角色库，再优先保留相同情绪标签的候选。
4. 在候选中按情绪 embedding 余弦相似度排序，只选择已人工批准且音频存在的参考。
5. 没有同类候选时回退该角色的中性身份参考；角色也不存在时继续使用当前原声并提示人工，不得跨角色借音。
6. 同一个参考音对应的 Qwen `voice_clone_prompt` 可在单次任务进程内缓存复用；源 WAV、准确文本和 embedding 才是持久资产，不跨 Qwen 版本持久化 PyTorch tensor。

参考音建议为 3 至 10 秒。首版不拼接不连续音频、不按固定七八种情绪预建空槽位，也不把表演相似度等同于情绪强度。

Qwen Base 当前公开接口不提供克隆音色上的独立自然语言情绪指令。将长参考音的 speaker embedding 与当前短音频的语音编码混合属于未公开验证的实验能力，不进入首版；只有真实 A/B 明确优于标准克隆后再单独立项。

### 12.6 校对 UI 最小调整

在现有 clone 校对工作台上增加最少信息：

- 顶部增加“角色库目录：未选择 / 选择”；同一部剧只需选择一次。
- “人物建议”改为可确认的角色下拉框，已有角色来自 `library.json`，允许创建一个新角色。
- 增加紧凑的“情绪”列，显示主标签和声音事件；低置信度或多模型冲突时才突出提示。
- 播放仍使用当前原声；参考音被替换时允许额外试听最终参考。
- 主按钮改为“确认人物、情绪与分组，开始配音”。
- 配音完成后只询问是否将本集检测出的优质新片段补充进角色库，不自动入库。

不新增独立人物管理页、情绪编辑器或角色关系图。真实多集使用证明校对工作台无法承载时，再考虑独立角色库界面。

### 12.7 失败与降级

- emotion2vec 下载或推理失败：保留当前克隆流程，使用当前原声，不阻断任务。
- embedding 文件缺失、损坏或维度不匹配：跳过该候选并记录警告，不重建整个角色库。
- 人物未确认：禁止使用角色库参考音，只能使用当前原声。
- 当前音频过短且角色库无候选：提示质量风险后继续，不选择其他角色。
- SenseVoice 与 emotion2vec 标签冲突：参考检索只服从 emotion2vec；SenseVoice 事件作为风险提示，Gemini 不自动覆盖音频结果。
- 参考音包含多人重叠、BGM、哭声等事件时必须保留事件元数据；是否可用由人工确认，而不是仅按时长自动入库。

### 12.8 实施顺序与验收

```text
1. 复用现有说话人分类
   -> 验收：继续由 speaker.json 给 Gemini 提供音频人物提示，不新建第二条说话人管线
2. 接入 emotion2vec+ large（唯一新增情绪主模型）
   -> 验收：完整轮次输出 9 类分数与可复现 embedding，失败不阻断任务
3. 保存稳定人物与角色库，并兼容保留已有 SenseVoice 标签
   -> 验收：A -> B -> A 可绑定两个 character_id，下一集可复用同一角色
4. 同角色情绪检索
   -> 验收：短愤怒台词只从该角色候选中选出相近长参考，不跨角色
5. 接入 Qwen 克隆并缓存 prompt
   -> 验收：短句音色漂移低于当前逐句参考，现有时间轴和字幕不变
6. 真实样片 A/B
   -> 验收：至少覆盖平静、开心、愤怒、悲伤、哭声、短句和角色切换
7. 再评估 Mage-VL
   -> 仅当音频与剧情冲突仍造成明显误判时考虑，不作为前置依赖
```

首轮 A/B 必须同时保留“当前逐轮参考”和“角色库检索参考”两套结果，由人工盲听比较音色一致性、情绪贴合度、开头瑕疵和跨语言自然度。没有真实样片结果前，不宣称角色库方案优于当前实现。

### 12.9 实施结果（2026-07-31）

- 已复用现有 `speaker.json` 和 Gemini 人物/轮次建议，没有新增说话人识别管线。
- 校对窗口已支持选择剧集角色库、编辑稳定人物 ID、查看并修改 emotion2vec 情绪、确认“接上句”，分别保存 `speaker_assignments.json`、`emotion_overrides.json` 和 `turns.json`。
- 已接入 `emotion2vec+ large` 官方模型；实测输出 9 类分数和 1024 维 embedding。
- 当前完整轮次达到 3 秒时仍优先使用自身；用户勾选后可将本集长参考加入角色库，短句只在同一角色内检索，不存在候选时继续使用当前原声。
- 情绪下拉框显示中文名称，落盘仍保存 emotion2vec 标准英文标签；“接上句”冲突必须提示具体行号、人物或情绪差异并定位到错误行。
- 第 2 步支持“保存并暂停/继续校对”：暂停时保存字幕、人物、情绪和轮次草稿并保留当前任务线程，当前应用会话内可从主按钮返回原校对窗口。
- 已验证“同角色长参考供短句复用”和“无候选时不跨角色借音”；真实整集声音效果 A/B 尚待用户试听。
