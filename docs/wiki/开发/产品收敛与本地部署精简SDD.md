# 产品收敛与本地部署精简 SDD

> 状态：已实施，macOS 本地代码与自动测试已验证；Windows 和全新机器真实短样片待目标环境验收
> 范围：赚钱音浪主仓库
> 目标：保留短剧字幕翻译与本地 Qwen3-TTS 克隆主链，移除主仓库中的去硬字幕组件，降低默认本地部署负担。

## 1. 背景

当前仓库同时包含主产品、去硬字幕 Git 子模块、多个历史识别/翻译/配音渠道和大量可选依赖。用户的实际主流程是：

```text
导入已有视频
  -> SenseVoice 中文识别
  -> 云端剧情翻译
  -> 人工校对角色、情绪和发言轮次
  -> 本地 Qwen3-TTS 声音克隆
  -> 字幕校准
  -> 最终视频合成
```

去硬字幕功能改为独立仓库维护，不再作为主产品部署前提。用户需要时单独下载使用；主产品只处理已经准备好的视频。

## 2. 目标与非目标

### 2.1 目标

1. 从主仓库移除 `tools/video-subtitle-remover` 子模块、入口和部署说明。
2. 将实验制作项目从六阶段改为五阶段：中文识别、剧情翻译与轮次、英文克隆配音、配音字幕校准、最终合成。
3. 中文识别直接接受用户导入的原视频，不再要求“去除硬字幕”阶段完成。
4. 默认依赖只覆盖主产品实际链路；历史渠道改为可选依赖或后续删除。
5. Qwen3-TTS 只在用户首次使用时下载，并允许选择 0.6B 或 1.7B，不能同时默认下载。
6. 保留 Wiki 项目、人工校对、角色参考库、API 配置、CLI 兼容边界和原有媒体合成能力，除非验收证明它们属于未使用的历史入口。

### 2.2 非目标

- 本阶段不制作 DMG、EXE 或其他独立安装包。
- 本阶段不把所有 Python 依赖打进 Git 仓库。
- 本阶段不删除本地 `models/` 缓存；该目录已被 Git 忽略，不影响 GitHub 克隆体积。
- 本阶段不合并去硬字幕仓库的 Python 环境；该功能已从主产品范围移除。
- 本阶段不重写六步项目的 Wiki 存储格式和人工校对规则。

## 3. 目标部署形态

用户从 GitHub 克隆主仓库后，只需准备主环境并启动桌面应用：

```text
git clone
-> uv sync
-> uv run sp.py 或打开赚钱音浪.app
-> 配置云端 API
-> 首次使用时选择并下载一个 Qwen3-TTS 模型
```

“内置渠道”只表示软件代码原生支持该渠道，不表示模型权重已经随仓库下载。SenseVoice、emotion2vec 和 Qwen3-TTS 均按使用阶段下载到本地 `models/`。

## 4. 目标主链依赖

默认环境只保留以下能力所需依赖：

- PySide6 桌面界面。
- FFmpeg、音频读取、字幕解析、音画同步和最终合成。
- FunASR/SenseVoice 中文识别。
- 云端翻译与人物/轮次建议 API 客户端。
- Qwen3-TTS 本地推理及 Torch/音频运行时。
- emotion2vec+ 参考音分析和角色声音库检索。

以下内容不进入默认环境：

- F5-TTS、Whisper、pyannote、OmniVoice、ChatterBox、MOSS、Confucius 等未使用本地渠道。
- 其他云厂商 SDK，除非主链实际仍调用。
- WebUI、Docker、Whisper.NET 和 CUDA 专用安装路径。
- 去硬字幕仓库及其 Paddle、OpenCV、独立 Python 环境。

源码入口是否保留，按“是否仍被主链调用”判断；不先通过删除源码来代替依赖清单收敛。

## 5. 实施阶段

### 阶段 0：建立基线

- 固定当前制作项目的真实短样片。
- 记录五阶段目标输出和当前测试结果。
- 确认主仓库外部去字幕仓库地址和独立使用说明。

验收：当前版本样片流程可复现，失败时有明确日志和产物边界。

### 阶段 1：移除去硬字幕边界

- 删除 Git 子模块引用和主仓库中的去字幕调用代码。
- 从项目状态、阶段列表、窗口入口、Wiki 模板和 README 中删除去硬字幕阶段。
- 中文识别直接以用户导入视频作为输入。
- 保留外部仓库链接和“先自行准备无硬字幕视频”的说明。

验收：创建项目后可以直接导入视频并运行中文识别；主仓库不再初始化去字幕子模块。

### 阶段 2：收敛默认依赖

- 根据阶段 0 的真实调用链整理默认依赖。
- 将确实还需兼容的旧渠道放入可选依赖；无法确认仍被使用的包暂不删除源码，只从默认安装移出。
- 重新生成 `uv.lock`。

验收：全新环境执行 `uv sync` 后，桌面主链可以启动；导入、识别、翻译、校对、配音、校准和合成均可运行。

### 阶段 3：Qwen 模型按需选择

- 在本地 Qwen3-TTS 设置或制作项目入口提供 `0.6B` 和 `1.7B` 选择。
- 首次使用只下载当前选择的 Base 模型。
- 不自动下载另一尺寸模型，不把模型权重提交到 Git。
- 在界面明确标注“内置渠道，模型首次使用时下载”。

验收：新环境分别选择 0.6B 和 1.7B 时，各自只产生对应模型目录，并能完成一轮配音。

### 阶段 4：删除确认废弃内容

- 根据阶段 2 的依赖和调用扫描结果，删除不再提供的渠道、设置窗口、文档、测试和残留资源。
- 保留必要的上游兼容功能，避免为清理而破坏 CLI 或主流程。

验收：全库测试、Python 编译、敏感信息扫描和 `git diff --check` 通过；文档不再宣传已删除入口。

### 阶段 5：发布前验证

- 在全新 macOS 环境完成主链验证。
- 在至少一个 Windows 环境完成 `uv sync`、启动和短样片验证。
- 检查普通 GitHub 克隆不会拉取去字幕子模块。
- 更新 README、部署 Wiki 和变更记录。

验收：新用户不需要安装去字幕组件即可完成主产品五阶段流程；需要去字幕时能跳转外部仓库。

## 6. 提交边界

每个阶段单独提交并验证：

```text
test: 固定主链基线
refactor: 移除主仓库去硬字幕边界
deps: 收敛默认安装依赖
feat: 支持 Qwen3-TTS 0.6B/1.7B 按需选择
cleanup: 删除确认废弃的渠道与文档
docs: 更新部署说明和外部去字幕指引
```

在所有本地验收完成前不 push；每个提交都可以单独回滚。

## 7. 风险与处理

| 风险 | 处理 |
|---|---|
| 去字幕阶段当前是识别前置条件 | 阶段 1 同步修改阶段门禁和项目状态，不只删除 UI 按钮 |
| 主链存在隐式历史依赖 | 先做真实短样片和导入扫描，再删除依赖 |
| Qwen 当前实现默认 1.7B | 阶段 3 明确传递模型选择，并验证只下载一个模型 |
| Python/平台依赖差异 | 先保证 macOS 主链，再补 Windows 验收，不提前承诺未验证平台 |
| Git 历史仍可能较大 | 本阶段只清理当前内容；是否压缩历史另立任务，不与功能收敛混做 |

## 8. 完成定义

本 SDD 完成的标志：

1. 主仓库没有去硬字幕子模块和运行时依赖。
2. 实验项目五阶段可从原视频直接开始。
3. 默认部署不安装未使用的本地模型渠道。
4. Qwen3-TTS 0.6B/1.7B 可单选、按需下载。
5. 新环境能跑通真实短样片，并完成相应测试和文档更新。
